# Skill 开发与发布流程

1. 明确真实任务、输入输出和第一版边界，写验收条件。
2. 查同类 Skill，阅读指令与脚本，标注仓库级 Star、查询日期和证据；Star 不代表功能已验证。
3. 对照官方规范确定支持子集；不支持的功能明确跳过。
4. 独立目录实现 SKILL.md、确定性脚本、示例和中英文 README。
5. 先验证正常闭环，再测试失败、歧义、输入错误和网络边界；保存实际日志。
6. 修复问题并回归，多轮同输入测试只证明稳定性，不增加覆盖度。
7. 实际 Agent 行为测试与脚本测试分别报告，不用预设候选冒充模型实验。
8. 更新文档和限制后发布独立 GitHub 仓库，commit 简短；读取远端核对文件。
9. 达到验收节点后暂停，记录剩余问题，再开发下一个 Skill。

## api-regression 第一里程碑

OpenAPI 3.0 JSON → 无参数、无鉴权 GET 的响应状态契约清单 → 显式授权的本地回环服务执行 → 脱离真实业务的 HTTP 服务测试。先验证状态契约；参数生成、响应体 Schema、鉴权及 pytest 导出留待下一阶段，不能宣称已经实现。

参考：OpenAPI 3.0.3 https://spec.openapis.org/oas/v3.0.3 。检索发现 zeroclaw-labs/zeroclaw-skills 的 api-tester；尚未完成其源码和 Star 核验，不作为已完成竞品评测。
